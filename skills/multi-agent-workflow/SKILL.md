# 多 Agent 项目工作流

将用户的当前目标交付到可检查的结果。先确定目标项目、完成标准和模式，读取该项目适用的 `AGENTS.md` 及已有启动、测试约定。

## 选择执行方式

- 用户指定“通过工作台运行”时，读取 [工作台接入](references/console.md)，使用已安装的本机控制台。
- 其他请求直接在当前 Codex 会话中协作。使用当前环境可用的子 Agent 工具；没有委派工具时如实说明，并由主 Agent 顺序完成，不能把角色文字当作实际子 Agent。
- 用户要求仅分析、规划或暂不修改时使用只读流程：分析、规划、审查，明确说明跳过实施。
- 用户要求制作、修复或落实方案时使用完整流程：分析与规划、实施、独立审查。不能交付方案后就声称实施完成。

## 分工与交接

1. 将现状分析与方案规划分给两个边界清楚的只读任务，独立部分并行执行。每个任务交接文件依据、结论、约束和未解决事项。
2. 等待所需前置结果，核对关键假设后开始实施。小任务使用一个执行 Agent；可独立的大模块可以分配不同文件或不同 worktree，提前约定接口。避免同时修改同一文件。
3. 将实际改动、相关验证和未完成事项交给独立审查 Agent。审查根据文件和运行证据核验，区分发现的问题与建议；主 Agent 处理必要修复并整合交付。

前置任务失败或用户要求停止时，停止依赖它的后续阶段。局部失败、未验证项目和权限限制要出现在最终结果中，不得当作成功隐藏。

## 项目与交付边界

当前项目的权限和用户指令始终有效；此 Skill 不授予额外目录访问、发布或对外发送权限。保留用户已有改动，不把本机路径、登录凭证或私人任务报告加入共享源码。

最终说明实际完成内容、结果所在位置、验证结果以及仍未完成的事项。需要可视化时使用已存在的控制台；不为了一个普通任务重复创建整套控制台。
